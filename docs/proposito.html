Visão, Propósito e Público-Alvo

Por que criar este projeto?

A web atual sofre com dois extremos: de um lado, sistemas monolíticos pesados e lentos (como versões legadas e infladas de CMS tradicionais) repletos de "gambiarras"; do outro lado, frameworks modernos e complexos que exigem uma curva de aprendizado altíssima e dependências infinitas via Composer.

O Domain-System nasceu da necessidade de encontrar o meio-termo perfeito: um sistema simples em sua essência (PHP puro), mas extremamente robusto em sua arquitetura (100% focado nos princípios SOLID e Padrões de Projeto).

Qual é o propósito?

Criar um Kernel (Núcleo) ultraleve, seguro e agnóstico, cujo único trabalho seja orquestrar aplicativos menores (Plugins) e Exibições (Temas). O núcleo não sabe o que é um "Paciente" ou um "Agendamento". Ele apenas fornece Ferramentas (Injeção de Dependência, Roteador, Banco de Dados Seguro) para que os Plugins façam o trabalho duro.

Dessa forma, criamos um SaaS White-label (Software as a Service) escalável. Se amanhã quisermos criar um sistema para Advogados em vez de Clínicas, o núcleo continua o mesmo, bastando apenas conectar novos Plugins.

Para quem é este projeto?

Para clínicas médicas, consultórios e desenvolvedores corporativos que precisam de um ecossistema flexível, rápido e próprio, sem pagar licenças milionárias ou ficar refém do código espaguete de terceiros. A estrutura é feita para desenvolvedores sérios que apreciam Clean Architecture e TDD (Test-Driven Development).

Como poderá ser estendido?

A escalabilidade é infinita. Graças à arquitetura Event-Driven (Orientada a Eventos), desenvolvedores futuros podem injetar comportamentos (via Filtros e Ações) sem nunca tocar no código original (Open/Closed Principle).

Você pode adicionar um Plugin de Gateway de Pagamento, um Plugin de WhatsApp Inteligente (Z-API), ou conectar o frontend via APIs REST, tudo isso respeitando o fluxo natural de rotas do sistema.
