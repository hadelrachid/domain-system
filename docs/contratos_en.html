Contracts and Interfaces

The Importance of Interfaces (SOLID)

In the Domain-System, we strictly apply the "Letter I" of SOLID (Interface Segregation Principle). Classes don't depend on each other, they depend on Contracts (Interfaces).

If the system expects you to extract ZIP files, it doesn't depend on the native ZIP library, it asks for an ExtractorInterface. This means tomorrow you can change the extraction method without breaking the entire system.

PluginInterface

Every plugin MUST sign this contract indirectly (by extending the abstract class AbstractPlugin). It dictates the lifecycle rules:

interface PluginInterface
{
    public function register(): void;
    public function boot(): void;
    public function activate(): void;
    public function deactivate(): void;
    public function uninstall(): void;
}

Explanation of Methods:

  • register() / osRegister(): The right place to negotiate capabilities with the Gatekeeper and register Routes, Event Listeners, and Dashboard Menus.
  • boot() / osBoot(): Executed after all plugins finish registering. osBoot(OsRuntimeInterface $runtime) is the 2.3 standard for safe Kernel access.
  • activate(): Run only once when you turn on the Plugin in the Dashboard (Ideal for Migrations and table creation).
  • deactivate() / uninstall(): Used to clean up the traces the plugin left when deactivated or deleted.

ManualModuleInterface (Manual Auto-Discovery v2.3)

Any plugin providing a manual/module.php file returning an instance of ManualModuleInterface is automatically discovered by PluginManualScanner and rendered inside the Cockpit's Instruction Manual (/admin/manual):

interface ManualModuleInterface
{
    public function getId(): string;
    public function getTitle(): string;
    public function getIcon(): string;
    public function getBadge(): string;
    public function getVersion(): string;
    public function getOrder(): int;
    public function getChecklistItems(): array;
    public function renderContent(string $baseUrl = ''): string;
}

This enables rich plugins (such as Academy LMS) to ship their own interactive documentation and QA homologation checklists with zero coupling to the Kernel source code!
