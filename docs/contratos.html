Contratos e Interfaces

A Importância das Interfaces (SOLID)

No Domain-System, aplicamos estritamente a "Letra I" do SOLID (Interface Segregation Principle). Classes não dependem umas das outras, elas dependem de Contratos (Interfaces).

Se o sistema espera que você extraia arquivos ZIP, ele não depende da biblioteca nativa do ZIP, ele pede um ExtractorInterface. Isso significa que amanhã você pode trocar o método de extração sem quebrar o sistema inteiro.

PluginInterface

Todo plugin DEVE assinar este contrato indiretamente (ao estender a classe abstrata AbstractPlugin). Ele dita as regras do ciclo de vida:

interface PluginInterface
{
    public function register(): void;
    public function boot(): void;
    public function osBoot(OsRuntimeInterface $runtime): void;
    public function activate(): void;
    public function deactivate(): void;
    public function uninstall(): void;
}

Explicação dos Métodos:

  • register() / osRegister(): O lugar certo para negociar capacidades com o Gatekeeper e registrar Rotas, Listeners de Eventos e Menus no painel.
  • boot() / osBoot(): Executado após todos os plugins terminarem de se registrar. O osBoot(OsRuntimeInterface $runtime) é o padrão 2.3 para acesso seguro ao Kernel.
  • activate(): Rodado apenas uma vez quando você liga o Plugin no Painel (Ideal para Migrations e criação de tabelas).
  • deactivate() / uninstall(): Usados para limpar os rastros que o plugin deixou quando for desativado ou deletado.

ManualModuleInterface (Auto-Descoberta de Manuais v2.3)

Qualquer plugin que possua um arquivo manual/module.php retornando uma instância de ManualModuleInterface é descoberto automaticamente pelo PluginManualScanner e injetado no menu Manual de Instruções (/admin/manual) do Cockpit:

interface ManualModuleInterface
{
    public function getId(): string;
    public function getTitle(): string;
    public function getIcon(): string;
    public function getBadge(): string;
    public function getVersion(): string;
    public function getOrder(): int;
    public function getChecklistItems(): array;
    public function renderContent(string $baseUrl = ''): string;
}

Isso permite que plugins complexos (como o Academy LMS) entreguem seus próprios tutoriais interativos e checklists de Homologação (QA) sem nenhum acoplamento com o código-fonte do Kernel!
