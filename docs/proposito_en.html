Vision, Purpose and Target Audience

Why create this project?

In modern web development, teams often encounter a common dilemma: traditional CMS engines that carry accumulated legacy code and heavy dependencies on one hand; complex frameworks that require extensive setup and dozens of third-party packages just to bootstrap a basic application on the other.

Domain-System was designed as a balanced, decoupled alternative: written in strictly-typed PHP 8.2+, featuring zero third-party runtime dependencies in the core, and structured around Clean Architecture and Dependency Inversion (DIP) principles.

What is the purpose?

To provide a lightweight, decoupled Core whose primary responsibility is managing foundational runtime infrastructure: dependency resolution via a service container, request lifecycle routing, fault tolerance (Circuit Breaker), and event dispatching.

The core has zero application-specific domain coupling. All feature sets — such as page management, visual theme building (Flex Builder), LMS, and SEO — are implemented as Plugins and SystemApps communicating strictly through interface contracts.

Who is this project for?

For developers, small teams, and production deployments that prioritize a predictable, lightweight footprint (~5 MB active Zend RAM and ~30 MB on disk), making it well-suited for cost-effective cloud instances or shared hosting environments, while backed by an automated test suite (over 430 tests in PHPUnit).

How can it be extended?

The architecture is designed for extension without core modification (Open/Closed Principle):

  • New Plugins: Created in src/Plugins/ by implementing OsExtensionInterface and registering routes, database migrations, and capabilities.
  • New Flex Builder Blocks: Extended by implementing BlockProviderInterface without altering core renderers.
  • Hooks and Events: Custom event listeners can intervene at key lifecycle stages using the central EventDispatcher.
