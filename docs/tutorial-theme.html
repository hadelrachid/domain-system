Domain-System OS

Guia Oficial de Construção de Temas de Alta Performance

Paradigma Visual (MVC)

No Domain-System OS, um Tema não deve possuir regras de negócio pesadas ou consultas ao Banco de Dados (SQL). A responsabilidade do Tema é exclusivamente a Camada de Apresentação (Views). Para lógica complexa de banco de dados, crie um Plugin. O Plugin processa os dados e entrega variáveis prontas para o Tema exibir!

Onde os temas vivem?

Todo tema deve ser construído na pasta do plugin controlador de temas, garantindo isolamento total do núcleo do sistema. O caminho exato é:

src/Plugins/flextheme/themes/{nome_do_seu_tema}/

A Estrutura de Pastas Exigida

Para manter o padrão da comunidade, seu tema deve possuir a seguinte organização arquitetural:

meu_tema/
├── theme.json           # O Manifesto (Nome, Autor, Versão)
├── layouts/             # A Casca Estrutural (HTML, HEAD, BODY)
│   └── main.php
├── partials/            # Componentes Reutilizáveis
│   ├── header.php
│   └── footer.php
├── templates/           # As Páginas Finais
│   ├── home.php
│   └── single.php
└── assets/              # Imagens, CSS puro e JavaScript
    ├── css/
    ├── js/
    └── img/

O Manifesto: theme.json

Assim como os plugins, o SO precisa saber que o seu tema existe. Crie o arquivo theme.json na raiz da pasta do seu tema:

{
    "name": "cyber_dark",
    "version": "1.0.0",
    "author": "Rachid",
    "description": "Tema oficial de alta performance."
}

O Motor de SEO e Performance

Minificação Automática

Nunca se preocupe em minificar seu código HTML. O **Domain-System OS** intercepta toda a saída do seu tema através de um Middleware de Performance, removendo quebras de linha e comentários na velocidade da luz antes de entregar para o navegador.

A Interface SeoManager

O Kernel do sistema injeta automaticamente uma variável chamada $seo (SeoManagerInterface) dentro do seu Layout. Ela é a responsável por gerar Meta Tags, Titles e gerenciar Redes Sociais (Open Graph) dinamicamente.

<?php
// Configurando o SEO no seu Theme Layout
$seo->setTitle('Página Inicial | Meu Site')
    ->setDescription('Aprenda tecnologia com alta performance.')
    ->setCanonical('https://meusite.com/inicio');
?>

<head>
    <!-- Isso vai gerar TODAS as meta tags (Title, Description, OG, Twitter) -->
    <?= $seo->generateTags() ?>
</head>

Layouts (A Casca Principal)

Todo site tem um cabeçalho, um rodapé e uma tag <body> que se repete em todas as páginas. Nós chamamos isso de Layout. Crie um arquivo em layouts/main.php.

Este arquivo deve incluir os partials (partes repetitivas) e imprimir a variável $content, que será injetada pelas Páginas (Templates).

<?php
// layouts/main.php
$seo->setTitle('Domain System');
?>
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <?= $seo->generateTags() ?>
    <link rel="stylesheet" href="assets/css/style.css">
</head>
<body>

    <!-- 1. Incluindo o Cabeçalho (Partial) -->
    <?php require $themeDir . '/partials/header.php'; ?>

    <!-- 2. Renderizando o miolo da página atual -->
    <main>
        <?= $content ?>
    </main>

    <!-- 3. Incluindo o Rodapé (Partial) -->
    <?php require $themeDir . '/partials/footer.php'; ?>

</body>
</html>

Templates (Criando as Páginas)

Os templates são as páginas finais (ex: a página inicial, a página de contato, a página do artigo). Eles usam a técnica de Output Buffering do PHP para "capturar" o conteúdo e enviá-lo para o layouts/main.php.

Exemplo: templates/home.php

<?php 
// 1. LIGA O GRAVADOR: Tudo que for renderizado abaixo não vai pra tela ainda, vai para a memória.
ob_start(); 
?>

<section class="hero">
    <h1>Bem vindo ao meu site de alta performance!</h1>
    <p>Aqui entra o conteúdo dinâmico ou fixo.</p>
</section>

<?php 
// 2. DESLIGA O GRAVADOR: Salva o conteúdo capturado na variável $content
$content = ob_get_clean(); 

// 3. CHAMA A CASCA: O layout main.php vai "imprimir" o $content lá dentro!
require $themeDir . '/layouts/main.php'; 
?>

Se você precisar acessar o Banco de Dados para popular essa página de conteúdos (ex: Listar Últimos Livros), use a classe do Controller (como o ThemeController) para buscar os dados via Repository ou faça uma chamada HTTP assíncrona. O Tema deve permanecer puro e escalável!
