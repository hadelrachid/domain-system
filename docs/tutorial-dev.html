Domain-System OS

Official Extension Building Guide (Themes & Plugins)

Critical Prerequisite

To build for Domain-System OS, you must understand Object-Oriented Programming (OOP) concepts. The system does not use loose global functions. Everything is based on Interfaces, Contracts, Classes, and Encapsulation.

The End of Global Mess

If you come from WordPress, you are used to creating a functions.php and using global functions. In Domain-System OS, this is strictly prohibited.

Every Extension (Plugin or Theme) is a Class that must sign a contract called OsExtensionInterface. This contract divides your plugin's lifecycle into two isolated security phases.

Dependency Injection (The Waiter)

Here, you don't hunt for system resources by instantiating random variables globally. The system works on a "Waiter" model: you sit down, ask for what you want (Phase 1), and the Operating System injects the ready tool right into your hands (Phase 2).

Phase 1: Negotiation (osRegister)

Before running any business logic, you use the OsConnector object to notify the Operating System what you will need to use. If you do not request permission here, you will be blocked in Phase 2.

public function osRegister(OsConnector $os): void
{
    // Requesting permission to read user data
    $os->requireLink('auth.user_reader');
    
    // Requesting permission to create a dashboard widget
    $os->requestSlot('admin.dashboard.alerts');
}

Phase 2: Execution (osBoot)

After approving your contract, the OS hands you the OsRuntime. This is where you actually work, receiving the requested resources strictly via Dependency Injection.

public function osBoot(OsRuntime $runtime): void
{
    // The OS INJECTS the tool into your hands
    $userReader = $runtime->getLink('auth.user_reader');
    
    // Now we can inject our visuals into the UI (Slot)
    $runtime->contributeTo('admin.dashboard.alerts', [
        'message' => 'Plugin successfully booted!'
    ]);
}

Complete Extension Structure

Just create your class implementing the Interface. The Domain-System OS Kernel will automatically handle the rest.

namespace DomainSystem\Plugins\my_plugin;

use DomainSystem\Core\Plugin\AbstractPlugin;
use DomainSystem\Core\Contracts\OsExtensionInterface;
use DomainSystem\Core\Plugin\OsConnector;
use DomainSystem\Core\Plugin\OsRuntime;

class Plugin extends AbstractPlugin implements OsExtensionInterface
{
    public function osRegister(OsConnector $os): void
    {
        $os->requireLink('core.session');
    }

    public function osBoot(OsRuntime $runtime): void
    {
        $session = $runtime->getLink('core.session');
        // Your safe, isolated code goes here!
    }
}
