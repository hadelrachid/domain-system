Priority System & Hook Resilience

Event Orchestration and Contingency Patterns in Domain System

The Administrative Recovery Pattern

In modular applications, critical middleware often needs guaranteed execution order (running strictly after or before other listeners). This is governed by the Hook Priority System.

How to Use Priorities

When attaching listeners via $runtime->onHook(), an optional third integer parameter specifies execution priority.

If omitted, the priority defaults to 0. Negative priorities execute earlier; positive priorities execute later in the cycle.

public function osBoot(OsRuntime $runtime): void
{
    // Default execution (priority 0)
    $runtime->onHook('admin.menu', function($menu) { ... });

    // High Priority - Runs LATER (e.g., Priority 999)
    $runtime->onHook('router.before_dispatch', function($uri) { ... }, 999);

    // Low Priority - Runs EARLIER (e.g., Priority -10)
    $runtime->onHook('router.before_dispatch', function($uri) { ... }, -10);
}

The Administrative Contingency Pattern

In SystemAdmin, the system listens to router.before_dispatch with priority 999 to act as a fallback guard for administrative routes.

If the standard authentication module is disabled or fails to initialize, this final check ensures unauthenticated requests to /admin are redirected to /admin/emergency for recovery access using the server's APP_KEY.

// Administrative Fallback Guard
$runtime->onHook('router.before_dispatch', function($uri) use ($sessionManager) {
    if (str_starts_with($uri, '/admin') && !str_starts_with($uri, '/admin/emergency')) {
        
        // If no session exists at this final evaluation point
        if (!$sessionManager->has('user_id')) {
            header("Location: " . BASE_URL . "/admin/emergency");
            exit;
        }
    }
}, 999); // Evaluates after standard authentication handlers

Execution Flow Organization

Hook priorities establish a predictable execution pipeline across independent modules:

  • Phase 1 (Priority < 0): Preparation, request pre-filtering, and diagnostics logging.
  • Phase 2 (Priority 0): Standard business logic and default extension handlers.
  • Phase 3 (Priority > 0): Fallback guards, response transforms, and administrative contingencies.
