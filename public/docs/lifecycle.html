O Fluxo de Vida do Plugin

Entendendo a abstração do Kernel através da analogia da Imigração.

Como o Domain-System OS impede que um plugin quebre o sistema inteiro? Ele não executa códigos cegamente. O Kernel segue um rigoroso processo de alfândega em 3 etapas. Clique nas etapas abaixo para entender a mágica.

🛂 1. O Passaporte (JSON)

A verificação de identidade antes do código.

A primeira coisa que o Kernel faz é ler o arquivo plugin.json. Nenhuma linha de código PHP foi executada ainda. O Kernel apenas olha o documento e avalia: "Quem é você? Qual sua versão? Você precisa de outro plugin para funcionar?". Se algo estiver corrompido, ele barra a entrada aqui, evitando a famosa "Tela Branca da Morte".

{
    "name": "test_os",
    "version": "1.0.0",
    "description": "Plugin de Teste para o novo Sistema Operacional Web",
    "core": false,
    "dependencies": []
}

🤝 2. A Entrevista (Negociação)

O Método osRegister()

Se o passaporte estiver válido e ativado, o Kernel carrega o seu arquivo PHP. Mas ele não deixa você trabalhar ainda! Ele chama você para uma sala de entrevista (osRegister). O Kernel pergunta: "O que você vai precisar usar aqui dentro?". Você responde anotando na prancheta do conector.

public function osRegister(OsConnector $os): void
{
    // Anotando na prancheta o que eu preciso
    $os->requireLink('core.session');
    $os->requestSlot('admin.menu');
}

🛠️ 3. O Crachá (Execução)

O Método osBoot() e a Injeção de Dependências

Com a entrevista aprovada, o Kernel finalmente te entrega o crachá de acesso (OsRuntime). Ele diz: "Pode começar a trabalhar! Aqui estão as ferramentas que você pediu.". Através do Runtime, o SO injeta as dependências diretamente na sua mão. Se você tentar pegar algo que não pediu no Passo 2, o crachá é bloqueado imediatamente.

public function osBoot(OsRuntime $runtime): void
{
    // O SO te entrega a sessão pronta e segura
    $session = $runtime->getLink('core.session');
    
    // O SO deixa você desenhar no menu administrativo
    $runtime->contributeTo('admin.menu', [
        'title' => 'Minha Clínica'
    ]);
}

🧩 4. O Código Completo

Juntando todas as peças

Veja como fica o arquivo final da sua Extensão, com os "uses" (namespaces) obrigatórios e o método legado exigido pela arquitetura de transição.

namespace DomainSystem\Plugins\test_os;

// Importação dos Módulos do OS
use DomainSystem\Core\Plugin\AbstractPlugin;
use DomainSystem\Core\Contracts\OsExtensionInterface;
use DomainSystem\Core\Plugin\OsConnector;
use DomainSystem\Core\Plugin\OsRuntime;
use DomainSystem\Core\Http\SessionManager;

class Plugin extends AbstractPlugin implements OsExtensionInterface
{
    // Método Legado (ignorado pelo OS novo, mas exigido)
    public function register(): void {}
    
    public function osRegister(OsConnector $os): void
    {
        $os->requireLink('core.session');
        $os->requestSlot('admin.dashboard.alerts');
    }

    public function osBoot(OsRuntime $runtime): void
    {
        /** @var SessionManager $session */
        $session = $runtime->getLink('core.session');

        error_log("🚀 BINGO! O Plugin TestOS foi aprovado!");
        
        $runtime->contributeTo('admin.dashboard.alerts', [
            'type' => 'success',
            'message' => 'O novo Sistema Operacional Web está operante!'
        ]);
    }
}
